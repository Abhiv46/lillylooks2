## What was implemented

### P1-1 — Real links everywhere
- `script.js`: `productCardHTML` now renders `<a class="product-card" href="product/<slug>.html">` (same classes/design; global CSS already neutralises anchor styling, and cards are grid items). `attachCardLinks` skips anchors. `renderProducts` detects the server-rendered homepage grid and no longer wipes/re-renders it (no duplicates). `renderCategoryPage` returns early on pages without `?c=`, so it can never overwrite the new static category pages; its canonical now points at `category/<key>.html`.
- Generator: "More Products" cards on product pages are real anchors (sibling `<slug>.html` hrefs).
- `index.html`: the full 21-card product grid is server-rendered into `#productGrid` as anchors, byte-identical markup to what the JS template produces.
- New static category pages (P1-3) carry their products as anchor cards.
- Bonus, same defect: the 3 guide cards on `guides.html` were also `data-url` divs — now real anchors to the guide pages.

### P1-2 — Meta descriptions
- `products-data.js`: every product gained a hand-written `metaDesc` (145–158 chars, complete sentences, keyword-led, written only from the product's existing description — no new claims). The generator now uses `metaDesc` for the meta description and the og/twitter descriptions (truncation function kept only as a fallback if a future product lacks `metaDesc`).

### P1-3 — Category pages
- Generator now builds 4 static pages: `category/skin.html` (7 products), `category/face.html` (4), `category/lips.html` (4), `category/tools.html` (6). Each has a unique title (48–58 chars) and meta (156–158 chars) from new `pageTitle`/`pageMeta` fields added to `CATEGORIES` in `products-data.js`, the category H1 (`heading`), the existing category `intro` text, static anchor product cards, and a statically rendered ItemList JSON-LD.
- `sitemap.xml` (via generator): the 4 `category.html?c=…` URLs removed, the 4 `category/<key>.html` URLs added — still **30 URLs** total, and every sitemap URL maps to a real file.
- All links to `category.html?c=…` updated to the new URLs: footers in `index.html`, `guides.html`, the 3 guide pages, `404.html`, legacy `category.html`, the generator template (product + category pages), the in-article category links inside the 3 guides, and `llms.txt`. The legacy `category.html` shell itself is left in place (no longer linked or in the sitemap; its JS renderer still works if visited with `?c=`).

### P2-1 — Fonts
- The unused Fraunces + Inter stylesheet link removed from: `index.html`, `guides.html`, all 3 `guide-*.html`, `404.html`, legacy `category.html`, and the generator template (so all 21 product pages + 4 category pages). Cormorant Garamond + Jost link kept everywhere.
- **Weights not trimmed:** `style.css` uses weights 300/400/500/600 across both families without a clearly separable per-family mapping, so per the brief the requested weights were left untouched.

### P2-2 — Titles / metas
- Homepage title: "LillyLooks | TikTok Viral Beauty Shop UK – Skincare & Makeup" (60 chars). Homepage meta: 156 chars, still ends "…available on TikTok Shop." (og/twitter descriptions updated to match).
- Guides index meta: 158 chars.
- Guide titles: 59 / 56 / 63 chars (≤65). Guide metas: 151 / 149 / 153 chars.

### P2-3 — Image dimensions
- All product images are square (checked every file: 1:1, mostly 800×800). Card, detail and guide-pick `<img>` templates (generator + `script.js`) now carry `width="800" height="800"`; `.product-img` already enforces `aspect-ratio: 1/1`.
- Logos (natural size 756×199, verified) gained `width="756" height="199"` attributes in the generator template and all static templates; CSS display sizing unchanged.
- QR images gained `width="180" height="180"` (see P3-4).

### P2-5 — Breadcrumbs
- Product pages: BreadcrumbList (Home → category name → product, using the NEW category URL) added to the JSON-LD `@graph` by the generator.
- Guide pages: BreadcrumbList (Home → Guides → guide headline) added as a second JSON-LD block.

### P2-6 — Guide headings
- All 5 article-section H3s in each of the 3 guides promoted to H2; "The Product(s) in This Guide" was already an H2 and stays the closing H2. No CSS selector targeted those H3s; because browsers size H2 larger than H3 by default, one compensating rule was added to `style.css` — `.product-detail .about-copy h2 { font-size: 1.17em; margin: 1em 0; }` — scoped so it cannot touch the homepage About H2, keeping the rendered design identical.

### P2-7 — product.html retired
- Replaced with a redirect stub: JS validates `?p=<slug>` and `location.replace()`s to `/product/<slug>.html`; bare/invalid values go to `/index.html#products`; a `<meta http-equiv="refresh">` fallback and a plain link cover no-JS cases. Self-canonical and generic product meta removed; the stub is `noindex, follow`.

### P3-2 — Product-name H2s
Generator template: "How to Use the <Product Name>" and "<Product Name> — Questions & Answers" on all 21 pages; "More Products You'll Love" unchanged.
