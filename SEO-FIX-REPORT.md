## 1. Repo structure findings (Step 1)

- **Product data source:** `products-data.js` — a `PRODUCTS` array of 21 products, each with `name`, `desc`, `img`, `category`, `badge`, `price`, `howto[]` (3–4 steps) and `faq[]` (2–3 Q&As). Slugs come from `productSlug()`: lowercase name, non-alphanumerics → hyphens (e.g. `neck-chin-tightening-cream-with-roller`). The same file holds `CATEGORIES` (4 category landing definitions) and homepage `REVIEWS`.
- **Rendering (the problem):** `product.html` is an empty shell — `script.js` reads `?p=<slug>` and injects all content, title, meta and JSON-LD with JavaScript. Product cards everywhere (homepage `#productGrid`, category grids, guide "picks", "More products") are `<div>`s with a `data-url` attribute and a JS click handler — **there were no crawlable `<a>` product links anywhere**. Crawlers therefore saw one generic page ("Beauty Product | LillyLooks UK") for all 21 products.
- **Homepage:** `index.html` renders its grid via JS, but also contains a static JSON-LD `ItemList` of all 21 products using the old `product.html?p=` URLs.
- **Guides:** the 3 guide pages contain 4 real inline `<a href="product.html?p=…">` links plus JS-rendered pick grids.
- **Sitemap:** `sitemap.xml` is a **static file** (30 URLs: homepage, 21 × `product.html?p=`, 4 categories, guides index + 3 guides, with image entries). `robots.txt` already points to it.
- **Prices in repo before this fix:** only ONE product had a price — Neck & Chin Cream at **£4.75** — and its own FAQ text repeated £4.75. All other 20 products were `price: ""` (no price shown anywhere).
- **Domain convention:** the whole site canonicalises to **non-www** (`https://lillylooks.co.uk`) — sitemap, canonicals and `SITE_URL` in script.js. See deviation note D1.

## 8. Deviations & things I was unsure about

- **D1 — Domain form:** the task brief wrote feed links as `https://www.lillylooks.co.uk/…`, but the entire site canonicalises to **non-www** (`https://lillylooks.co.uk`). I used non-www everywhere (pages, canonicals, sitemap, feed) so feed links match landing-page canonicals exactly — a www/non-www mismatch is a classic Merchant Center warning. Both forms resolve to the same site; if www is preferred, it is a one-line change in the generator (`SITE_URL`) plus the same change would be needed across the existing site.
- **D2 — Feed count 17, not 19:** explained in §5. Caused by the "never invent a price" rule meeting two in-stock products with no verified single price.
- **D3 — One copy edit beyond prices:** the Neck Cream FAQ answer said "It is £4.75 here on the site." Leaving it would have contradicted the corrected £9.50 price on the same page, so the figure was updated to £9.50 in `products-data.js` (a factual price correction only — no claim wording changed).
- **D4 — Out-of-stock visible note:** I judged the existing `.detail-note` line safe (same pattern as the showcase note directly above it) and added it for the 2 out-of-stock products; schema also carries OutOfStock. Remove one line in the generator if unwanted.
- **D5 — Homepage ItemList schema:** URLs and the one existing price were updated, but the other 20 offers in that block still carry no price (their previous state). Full prices live in `products-data.js`, the static pages and the feed. Adding them to the homepage block is a trivial follow-up if wanted.
- **D6 — Sitemap XML escaping:** the original sitemap had a raw `&` inside two `image:loc` URLs (not well-formed XML). The regenerated sitemap escapes correctly (`&amp;`).
- **D7 — Pre-existing working-tree state:** the repo already had unrelated uncommitted changes before this task (redesign files dated 20–21 Nov). Nothing was committed or pushed as part of this work.
- **Not in scope / still to do outside the repo:** creating the Merchant Center account and setting shipping there, then pointing it at `merchant-feed.xml`; resubmitting the sitemap in Search Console after the push so Google picks up the new URLs.
